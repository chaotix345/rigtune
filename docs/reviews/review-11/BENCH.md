## Checked, fine

- **Busy can't stick.** `running()` (`next`, `measuring`, `applyDue`, `applying`) always ends: WAIT_TICKS (30 s) and RUN_CAP_TICKS (20 min) run while `active`; `applying` resets in the derive's finally; `active` clears only when all are false. After a restart no live flag is set, and `Busy.tryItRunning` is wired only at the first queue. TryItFlow never derives MEASURING_* or APPLYING without a live flag, so a crash or quit mid-run resumes or closes on the next start (every crash point walked: before open, during before, before apply, after apply, during after, before acknowledge).
- **One claim per run.** `claim`/`onOutcome` claims only the try's pairId while `measuring`. M1 (`refused != null && measuring`) stops a failed begin that already handed over its outcome from being handled twice. `BenchmarkWorld.leave` runs `show` once.
- **Double close.** `TryItStore.close` checks the open id inside the read-modify-write. `closedHere` plus Done can't close twice. A second Keep or Done re-derives or finds no try.
- **KEPT/REVERTED.** KEPT only via `keep()` after a fresh derive still offers KEEP (M5), or NO_ENTRY's Done (fold proven by `foldedEntryIds`). REVERTED only from REVERTED/REVERT_PENDING. DISCARDED gives CANCELLED.
- **Revert and Cancel try** both open `UndoScreen(entryId)` (History's Undo this); there is no other revert path. TryItScreen waits for the re-derive after it (M5).
- **Verdict gating.** Conditions (minus the key's allowed set), Excluded (fresh world, DH generating; M4), Moved (CURRENT, fails closed on an unknown spot), Mods, History entries in the cursor window (time fallback fails closed), managed-settings snapshot. Noisy widens the floor (2 x CV) and adds a caveat, by design. SESSIONS is right for NOW-resumed and RESTART tries.
- **tryit.json vs 0.4.0.** A new file 0.1-0.4 never read. JsonStateFile rules apply (formatVersion 1, 16 KiB cap, `.bad`, newer read-only, unknown fields kept at every depth). Try It writes only ordinary apply/undo entries and existing op types. Pairs are free-string `tryit-` ids (compat table's accepted "0.4.0 may continue it"). A 0.4.0-made after run is NOT_COMPARABLE through the mod-set hash, since RigTune's version is in it.
- **X8.** tryit.json is read and written only on the ordered chain (Probes.EXECUTOR). The render thread only stats history.json, at most once a second while a try is open. The tick is one volatile read when idle. No startup I/O: the first derive is submitted by the start hook.
- **Threading.** Store, Journal, BenchmarkStore (synchronized) and TrendService.acknowledge (a concurrent set plus StateStore) are safe from the executor. The title-toast flags are handled (L9).
- **WS-B.** RenderDistancePlanner never proposes a distance it already measured and re-measures each incomplete distance at most once; the deadline keeps a repeat's time after a re-measure. ChangeWindow BH-2 (with the field, without it, carried-in rows) is right. `excluded` stays out of baseline and previousOfScene, a latest excluded run is EXCLUDED, and `Outcome.gain()` is null with `pairCaveat`. StutterSteps opens and closes symmetrically, cancel inside an excluded step included. `lastBenchmarkDhWorldGen` resets on every finish. `stagedAtStart` is `[]` or null as documented. BenchmarkMenuScreen's `tryit-` filter works. `show()` places the hook after the restore toast.
