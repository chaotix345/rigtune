## Checked, fine

- **Tested bytes = published bytes.** `build` stages exactly one main jar and one -sources jar per `versions/*/` node, with SHA256SUMS. e2e.yml's scenario, stutter-script and battery-oshi jobs all take `rigtune-*+mc$MC.jar` from that same `release-files` artifact. battery-oshi uses `-PgametestModJar`: build.gradle:435-440 `mods.setFrom(...)` drops the build's own jar, and the resolve step builds only `gametestJar`. `publish` re-checks SHA256SUMS and uploads those files to GitHub and to Modrinth (`-PmodrinthFile`, `-x assemble`). release_verify.py compares the GitHub asset's sha1/sha512 with Modrinth's metadata and with the CDN bytes (the token is not sent to the CDN), and checks number, game_versions, loaders and type for every node. Nothing is rebuilt after `build`.
- **Tag guard kept.** `grep -qxF "mod_version=${TAG#v}"` runs before anything is built. Dispatch is a dry run: no `gh release create`, Minotaur debug mode with an empty token (build.gradle:175 falls back to the placeholder on ''), and verify is read-only on `verify-tag`.
- **Token scope.** MODRINTH_TOKEN is only on the Modrinth step (tag push only) and the read-only verify step. At job level only a boolean is exposed. See CI-2 for what the Modrinth step itself exposes.
- **Release-tier matrix vs SPEC 3a:**
  - upgrades from 0.4.0/0.3.0/0.2.0 on both nodes, and 0.1.0 (`--legacy-disable --expect-history auto`) on 26.2;
  - seeded v010-dh (chattr +i) on 26.2, and both v010-dh-app-reinstalled seeds on 26.2;
  - undo profile/settings and helper-kill on both nodes; downgrade to 0.4.0/0.3.0 on both nodes;
  - brand-theseus on 26.2; battery-oshi and the stutter script per node. That is 21 rows plus 4 legs.
  - The generated seeds are ws-e's open residual (pending the coordinator), not repeated here.
- **Push tier.** 0.4.0 -> new on every node, from `rigtune-jars`. The release tier runs on a PR into main from `feat/v*` and on e2e.yml's own dispatch, never on build.yml's dispatch.
- **No silently ignored failure.**
  - `continue-on-error` appears only on the JDK first try. It is followed by `sleep 30` and an unguarded retry in every job of build/e2e/release (JdkRetryTests).
  - `|| true` appears only on diagnostics or cache copies. The game-test step propagates `$code`.
  - e2e.yml's `nodes=$(...)` inside `echo` would mask a failure, but an empty `fromJSON('')` then errors the dependent jobs, so the failure still surfaces.
  - Upload steps with `if: always()` are artifacts only. The e2e job's `!cancelled() && needs.* == success/skipped` gate is correct for a skipped `jars` job.
- **tools/ci/offline.sh:** netns with lo plus a multicast route. `timeout` runs as root before `setpriv`, and signals the process group. `--preserve-env` keeps CI/JAVA_HOME. The empty-array expansion is safe on bash 5.2.
- **tools/ci/retry.sh:** 3 tries; `status=$?` after `cmd && exit 0` is cmd's status.
- **check_fake_modrinth.py:** 206 counts as 2xx; 400/405/other 404s fail the leg; a rotated .gz is read.
- **MulticastCheck** also checks that 1.1.1.1:443 is unreachable.
- **Network use.**
  - Unit, Python and game tests run in the netns.
  - E2E Gradle runs `--offline` after the prefetch, and the game JVM resolves only the three redirected hosts (jdk.net.hosts.file). The rules are served by the fake.
  - The old jars are sha256-checked on every run, whether they came from cache or were downloaded.
  - The E2E drivers compile against the 7 pinned released jars.
- **ModrinthFixture/RulesFixtureServer:** loopback, port 0, lazy start. A failed start is sticky, so the build never falls back to live Modrinth. Shutdown closes stdin with a 10 s kill. The request log is appended per request.
- **GameTestNet** waits for a new report instance with the matching online state (1200 ticks). **GameTestWorlds'** hold is bounded at 30 s. **V05TestContext.resize** runs on the client thread.
- **E2E harness Linux path:** `/proc` listing and SIGKILL of its own processes only. The helper watcher thread is joined. `chattr +i/-i` sits in a `held()` context. helper-kill kills 1.5 s into a ~30 s retry budget, and either state is accepted. The midnight rollover is handled in `session_log`. The stale-seed/brand 5 s negative windows can't fail spuriously.
- **update_rules `--revision`:**
  - below the files' revision: refused;
  - at or below `origin/main`'s: refused;
  - when main can't be read: refused unless `--skip-main-check`;
  - unchanged content: nothing written;
  - under 2^31-2. The bot path is always old+1. See CI-6 for the merge-time gap.
- **Not reported:** the dormant 2-part split's part 2 now starts with a NEW player, because FirstApplyGameTest's `forceStatusForTests(RETURNING)` only covers later classes in the same JVM. I found no assertion that breaks on it (SERVER_PROFILE outranks FIRST_RUN, and StutterFixGameTest's own `apply` retires NEW). Worth one `-f gametest_parts=2` dispatch before the switch is ever flipped, since AC1g.4's proof predates C02.
