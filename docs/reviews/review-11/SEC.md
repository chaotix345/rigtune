## Checked, fine
- **RangeReader (L5) against a malicious CDN or MITM:**
  - Requests: the origin allowlist runs before any request; redirects are never followed; the Modrinth gate is checked before every request.
  - Responses: a 206 counts only with the exact Content-Range asked for and the same total every time; non-206 bodies are truncated to 0; a non-identity Content-Encoding is refused.
  - Archive checks: the EOCD search is bounded to the 64 KiB tail with an exact comment length; split archives and ZIP64 sentinels are refused; the central directory is capped at 2 MiB and must end before the EOCD; the entry count must match the directory; duplicate fabric.mod.json entries are refused.
  - Entry checks: sizes are capped at 1 MiB compressed and inflated before any request; the local header name is re-checked; the data may not run into the central directory; inflate is capped at size + 1, then size and CRC are checked.
  - Robustness: all offsets are longs, and the int casts are only on bounded values; a NumberFormatException from a huge Content-Range becomes a failed read; the reader is closed in try/finally.
  - Scope: it only affects Preview. Apply re-checks the SHA-512-verified jar.
- **`-Drigtune.modrinth.baseUrl`:**
  - Only https, or http on localhost / [::1] / 127.x (full match), is accepted; userinfo is refused.
  - HttpModrinthClient, RangeReader and RulesSources apply the same rule, and RangeReader grants no extra origin when HttpModrinthClient ignored the value.
  - Downloads check every redirect hop against the allowlist; a SHA-512 is required.
- **Share codes and profiles:**
  - Share code decoding enforces raw and stripped length caps, strict base64 with zero spare bits, a CRC, canonical varints below 2^31, count <= MAX_PAIRS, no duplicate keys, and `validWire` for every known key. That keeps key 22 at 32..512 on the wire, so a 0.4.0 decoder never sees out-of-range values; encode leaves out a radius above 512, and `leftOut` counts it.
  - `ShareKeys.number` caps input at 16 characters before BigDecimal.
  - profiles.json values go through `local()` with a 64-character cap and `safeValue`.
- **Launcher probe:**
  - InstanceEvidence reads at most 256 entries, names only, with NOFOLLOW on `.index` and on each entry; any Throwable counts as no evidence; it runs on Probes.EXECUTOR.
  - No code references Modrinth App's `app.db`, and InstanceFiles (the 32 MiB streaming reader of minecraftinstance.json) is unchanged.
- **Hand-edited stores (apart from SEC-1/2):**
  - JsonStateFile refuses files over 4x the cap before reading, decodes strict UTF-8, and moves corrupt files to `.bad`.
  - FixStore, TryItStore, ServerProfileStore, StartupTimesStore and AwarenessStore type-check every value.
  - SessionOutcome zeroes negative and non-finite values; FixComparison caps n at MAX_N and clamps phi; the prune and fit loops terminate.
  - StartupTrend divides only by positive medians (runs with ms <= 0 are filtered out; preloadMs must be < ms).
  - Instant comparisons and `Duration.between` never throw.
  - A try's Revert goes through History's Undo this (with Preview), never through tryit.json's key or values.
- **Rules (stutterFixes):**
  - LenientEntries drops only the bad entry; `requires` must name only supported features.
  - FixSpec allows only its 3 keys, values must decode through the ShareKeys table, steps are 1..8, and bounds are clamped to the table's range.
  - Gson never turns a number literal over 1024 characters into a number.
  - The v2 4i condition `<0.5.0-` is FALSE on 0.5.0 and its pre-releases (only the v1 path leaks: SEC-3).
  - `update_rules.py`: the validator mirrors FixSpec; `--revision` can't go below the current revision and must be above main's (git is called with list arguments and a timeout).
- **Sanitisation:**
  - `LogSafe.error` now escapes and caps each part; OnlineDataFetcher's new log lines use it.
  - The share report's new "Mod files" line goes through `MarkdownSafe.field` with fixed launcher names.
  - CrashReportMixin only times `preload` (require = 0).
- **Dev hooks:**
  - `DevFixCalibration.tick` returns first unless `-Drigtune.dev.stutterScript=fixcalibrate`, and StutterFixService's dev log is gated by `ON`.
  - DevStutter needs `teleport`, or `forceGcEverySec` > 0.
  - TryItDevRun is loaded only when `RIGTUNE_DEV_TRYIT` is set: `TryItService:298` reads a compile-time constant.
- **Workflows:**
  - No `pull_request_target`.
  - Inputs, the tag and matrix values reach shells only through env, quoted; the tag must equal `v<mod_version>`; `HARNESS_ARGS`'s eval is a `shlex.join` of the repo's own table.
  - MODRINTH_TOKEN is only on the push-only publish step and the read-only verify step, and `release_verify.py` doesn't send it to the CDN URL.
  - The build job has `contents: read`, and the reusable e2e workflow gets no secrets.
  - Old-jar caches are re-checked by sha256; Gradle caches are written only from main and feat/v0.5.0 (tag runs read main's).
