# WS-E design notes: settings screen, network switches, share report, RigTune screen buttons

SPEC items 8 and 10 (P1). Plan: docs/v0.2/plans/ws-e.md.

## Settings (item 8)
- All switches live in `ClientSettings` (`config/rigtune/settings.json`), never in ClientState/rigtune.json (plan review M2): `networkEnabled` (master), `remoteRules`, `modrinth`, `startupToast`, `benchmarkScene` (BenchmarkRequest.Scene names; `benchmarkSceneOrDefault()` maps null or unknown names to CURRENT), `privacyNoticeShown`. A missing, partial or corrupt file gives the defaults for the missing fields (Gson + field initialisers). 0.1.0's rigtune.json keeps loading goal and lastShownApply and doesn't affect the switches (ClientSettingsTest).
- The default goal is not duplicated into settings.json: the settings screen's goal button goes through `controller.setGoal`, which keeps using rigtune.json as 0.1 did.
- `RigTuneSettingsScreen`: one centred column (≤ 310 wide) of CycleButtons: Network access, Rules updates (GitHub), Modrinth, Startup suggestions toast, Default goal, Benchmark scene (WS-C's `rigtune.benchmark.scene.*` labels; the benchmark world only when `BenchmarkWorld.supported()`, as in WS-C's menu, which reads the same setting). Each tooltip says what the switch sends. The two finer network switches are greyed out (inactive, value kept) while the master is off. A change sets the shared `ClientSettings` field at once and writes settings.json on `Probes.EXECUTOR` (each write serialises the live object, so the last one always has every change). The three network switches then call `controller.settingsChanged()` (the contract default rescans; WS-A adds the rules reload). Startup toast and scene only save; the goal goes through `setGoal` (which rebuilds).
- Mod Menu's config button opens the settings screen; it has an "Open RigTune" button to the main screen, shown only when its parent isn't the RigTune screen (from there, Done goes back).
- Privacy toast: `StartupNotices.takePrivacyNotice(settings, configDir, executor)` returns true once, sets `privacyNoticeShown` at once and saves on the executor; RigTuneClient shows it with the other title-screen notices. `StartupNotices.showSuggestionsToast` gates only the "RigTune: N suggestions" toast; apply results, warnings and the privacy toast are unaffected.

## Network gating
- Modrinth: `core/modrinth/GatedModrinthClient` wraps the HTTP client in RealController and reads `settings::modrinthAllowed` on every call; while off, every method throws `ModrinthException(0, …)` before touching the delegate. That one seam covers installed-jar lookups, update checks (including RigTune's own), availability checks, dependency resolution and downloads, whatever code path calls them. Tests use a client whose every method fails the test.
- RealController: `fetchOnline()` short-circuits to offline data (no log noise, and stale online data is dropped); `rebuild()` uses `OnlineData.offline()` while Modrinth is off (so a report built right after the switch can't reuse old update data) and passes the result through `core/report/ModrinthOffAdvice`: AddMod/UpdateMod recommendations keep their id, category, impact and title but get `Action.None`, unticked, with "Modrinth is off in RigTune's settings: install it from your launcher." (or "update it in your launcher.") appended. They stay in their Add/Update groups rather than moving to Advice, like 0.1's "outside the mods folder" updates. `rescan()` bumps the build generation (on the render thread) so a report still being built from before a settings change can't be published after it.
- Header: with the network off the RigTune screen adds a line "Offline (network off in settings): add and update mods in your launcher"; with only Modrinth off, "Modrinth off in settings: …". It's its own header line, so it can't be clipped away at the end of the display/rules line.
- Remote rules: WS-A's `RulesSources.remote()` asks `ClientSettings.remoteRulesAllowed()` (network and rules switches) before each request, wired in `RealController.loadRules` (WS-A's RulesSourcesTest: `noRequestWhenRemoteNotAllowed`, `noFallbackRequestOnceRemoteIsSwitchedOff`). WS-A's `settingsChanged()` reloads the rules, then rescans.
- With WS-A's `OnlineLookupGate` (one Modrinth lookup per scan and rules pair), the Modrinth-off check in `fetchOnline()` runs before the gate, so a lookup isn't used up while Modrinth is off; turning it back on goes through `settingsChanged()`, whose rescan makes a lookup due again.

## Share report (item 10)
- `core/report/ShareReport.format(report, versions, benchmark[, maxChars])`, pure and English-only (it's pasted into Discord/issues, like the rules' reasons). Sections: versions line; Hardware (CPU with cores/threads, GPU + driver + backend + VRAM, RAM/heap/display with refresh, tier + limiting factor + goal, rules revision/source + online/offline); Latest benchmark (or "not run yet"); Recommendations grouped by Category order, `[x]`/`[ ]` for appliable ones, no box for informational ones, with the impact. Titles only: reasons and Action fields (file paths) are never included.
- `[x]` means "suggested" (`selectedByDefault`): the controller contract `shareReport()` has no view of the screen's current ticks, and the legend says so.
- Every free-text field (hardware names, mod titles, versions) is: scrubbed of path-like text, replaced by "(path)" (drive, `~` and absolute Unix paths whose folders may contain spaces, plus any word with a backslash; URLs and "a / b" or "1/2" survive); clipped to 120 characters without splitting a surrogate pair; Markdown-escaped (`\ * _ ~ ` | [ ] <`) with a zero-width space after every `@`, so a mod title can't format the message or ping anyone.
- Limit: 2000 characters by default. Recommendation lines are dropped from the end, keeping as many as fit together with the "(N more)" line; a category header only appears with its first item. If even "(N more)" doesn't fit it's left out (the Recommendations line has the count). If the fixed part alone is too long, the text is cut at the last whole line that fits (a character cut with "…" only if none does); a limit ≤ 0 gives "".
- The Copy report button uses `Minecraft.keyboardHandler.setClipboard(String)`, verified identical on 26.2 and 26.3 with javap (no Stonecutter conditional). The status line says how many characters were copied.

## RigTune screen buttons
- Title row: a Settings button at the right edge; the goal button and the tier badge make room for it (the badge falls back into the header lines when it doesn't fit, as before).
- Footer, in order: Apply, Undo last, Undo all, [Discard pending], Benchmark…, Rescan, Copy report, Done. Undo opens `new UndoScreen(this, controller, all)`, Benchmark opens `new BenchmarkMenuScreen(this, controller)` (both owned by other workstreams; the Benchmark button no longer needs a world, the menu decides). Grid: as many buttons of ≥ 88 px per row as fit, then the rows are balanced; at 427×240 and 426×240 that's 2 rows of 4 (95 px), at 640×360 2 rows of 4 (117 px), at 320 wide 3 rows of 3.
- The Benchmark button's label is `rigtune.screen.benchmark_menu`; the older `rigtune.screen.benchmark` and `.needs_world` lines are left untouched for WS-C.
